## 二、预期效果

**图拓扑**（涂总重点）

- 节点铺满画布、层次清晰，边不交叉成 spaghetti
- **点「计算选源」→ 源节点呼吸高亮、非源淡出、选中路径边流动起来** —— 让算法"看得见"
- 侧栏从"静态统计"变成"**本次选源结果**"：选中了哪几个源、每个源的 `strength / relevance / src_score` 分解条
- 鼠标悬停节点 → 邻域聚焦，其余淡出；可拖拽、可缩放、拖过的节点不被动

**对话窗口**（涂总重点）

- 消息**流式逐字出现**，不是等 3 秒后整段蹦出
- 四维打分、共享池注入**逐条展开**（stagger），让人看懂"调度发生了什么"
- 空状态、加载态、失败态都有明确视觉，不再静默

**全局**

- 暗色模式（跟随系统 + 手动切换）
- 卡片阴影分级、留白有节奏，信息密度上去但不觉拥挤

## 三、解决方案

### 3.1 先修功能缺陷（不是审美问题，是 Bug）

| # | 问题 | 修法 |
|---|---|---|
| B1 | 发问静默失效 | 未选中节点时**禁用发送按钮 + 灰态提示**「请先选择一个会话节点」；`return` 前 `flash()` 一条 |
| B2 | 选源零反馈 | 见 3.2，这是产品核心 |
| B3 | 侧栏与动作脱节 | 侧栏改成选源结果面板，实时反映最近一次选源 |

### 3.2 图拓扑（优先级最高）

**用现成方案，不手搓：**

| 能力 | 方案 | 说明 |
|---|---|---|
| 布局算法 | **`cytoscape-fcose`**（iVis Lab 维护，Cytoscape 官方生态） | 比 CoSE **快 2 倍**且美学相当；关键是它支持 **`fixedNodeConstraint`** —— 唯一能"用户拖过的节点不被布局算法挪走"的力导向方案，这是可编辑性的地基 |
| 节点尺寸 | `nodeDimensionsIncludeLabels: true` | 节点框随标签长度自适应，不再是固定尺寸卡片 |
| 有向层次 | 保留 `breadthfirst` 作 DAG 主布局（我们强制 DAG），但把 `spacingFactor` 从 1.12 提到 **1.8~2.2**、加 `circle:false` | 直接解决"挤在中间" |
| 高亮/聚焦 | Cytoscape 自带 `cy.animate()` + style `transition-property` | 已有能力，只是没用对 |

**选源动效序列**（核心，Canvas 原生即可）：

```
点击「计算选源」
  ① 全部节点 opacity → 0.25（180ms ease-out）
  ② 选中源节点 scale 1→1.15→1 + 描边发光，循环 2 次（每次 600ms）
  ③ 源节点之间的边改用虚线流动（line-dashoffset 动画，1.2s linear infinite）
  ④ 侧栏结果面板从右滑入（240ms cubic-bezier(.16,1,.3,1)）
```

**可编辑性**：

- 拖动节点 → 记入 `userMoved` 集合 → 后续布局用 `fixedNodeConstraint` 钉住
- 双击节点 → 侧栏展开该节点详情（摘要、记忆数、上下游）
- 滚轮缩放已有，补充缩放级别指示

**边降噪**：

- 成环被降级的边（`cycle_rejected`）默认隐藏，图例里可勾选显示
- `similar_to`（强度 0.3，最低）默认半透明

**图例**：从画布正中移到**右下角固定位**，改成竖排小卡片。

### 3.3 对话窗口

| 能力 | 方案 | 理由 |
|---|---|---|
| 流式响应 | **后端改 SSE**（`text/event-stream`），前端 `EventSource` 逐块追加 | 真流式，不是假打字机 |
| 消息入场 | **Web Animations API** 原生 `element.animate()`，`opacity 0→1 + translateY 8px→0`，180ms | 0 依赖 0 体积 |
| 四维打分逐条展开 | WAAPI + `delay: i * 60` 做 stagger | 同上 |
| 共享池注入滑入 | WAAPI，从右侧 `translateX(16px)` 进入 | 同上 |
| 打字机光标 | 原生 CSS `@keyframes`，十几行 | **不引库**（见 3.5） |

### 3.4 全局视觉

- **暗色模式**：`app.css` 已有完整 CSS 变量，只需补一组 `[data-theme="dark"]` 覆盖 + 一个切换按钮（存 localStorage）。成本最低、观感提升最大。
- 卡片阴影从 2 档扩到 3 档（`--shadow-1/2/3`），拉开层次
- 统计数字用 WAAPI 做 count-up（600ms）
- 空状态补插画/示意图标，不要只一行灰字

### 3.5 依赖选型（明确结论）

| 库 | 用不用 | 理由 |
|---|---|---|
| **`cytoscape-fcose`** | ✅ **用** | 布局算法没法手搓；`fixedNodeConstraint` 不可替代。UMD 本地化到 `static/vendor/`（约 55KB gzip），沿用现有 cytoscape 的本地化方式 |
| GSAP | ❌ 不引 | 24KB+ 核心体积，价值主要在时间轴编排；我们只需要 stagger + 微交互，**Web Animations API 原生就够**，且 0 体积 0 维护 |
| Motion One | ❌ 不引 | 3.8KB 很轻，但能力与 WAAPI 重叠度高，不值得多一个依赖 |
| Typed.js | ❌ **不引** | **GPL 许可**，开源项目商用有风险；且打字机效果原生几十行就能写 |
| framer-motion / react-spring | ❌ 不适用 | 本项目是原生 JS 单页，无框架 |

> 原则：**只有"手搓成本远高于引包"才引包**（fcose 属于这类）；
> 动效这类原生 API 已覆盖的，一律不引 —— 演示环境要能离线跑，依赖越少越稳。

## 六、D-054 真流式（补完 P2）

原计划里 SSE 只做了"占位气泡 + 阶段动画"，**不是真流式**。本轮补完。

### 改了什么

| 层 | 改动 |
|---|---|
| 模型适配器 | `complete_stream()` 增加 `thinking` 参数。原先固定"max_tokens>64 自动开思考"，导致流式回答会先吐一大段 reasoning；现显式传 `False`，与同场景的 `complete()` 一致 |
| Runtime | 新增 `main_answer_stream()`（生成器）+ `answer_prompt()`（流式与非流式**共用同一份 prompt**，避免两个界面回答不一致）。AgentScope 路径的 `agent.reply` 非流式，降级为一次性产出但仍切片推送 |
| 后端 | `/api/canvas/ask` 由一次性 JSON 改为 SSE，事件序列：`stage` → `round` → `stage(answer)` → `delta`×N → `done`。`round` **先于** `delta` 发，前端拿到就能先渲染四维表，不必等回答结束。`/api/chat` 的假流式（先算完整段再切片）也一并换成真流式 |
| 前端 | 新增 `ssePost()`：`fetch` + `ReadableStream` 逐块解 SSE（**不能用 `EventSource`**——它只支持 GET、不能带 body，而追问必须 POST）。收到 `delta` 就追加渲染 markdown 并滚到底部 |

### 踩到的两个坑（都很难查）

**① `complete_stream` 之前是假流式**
原 `_handle_chat_sse` 写的是 `main_answer()` 先算完整文本、再 `_slice_text()` 切片推送 —— 界面等待后整段蹦出。判别方法很直接：**看各条 delta 的到达时间戳**，预切片的间隔全是 0.001s 量级。改完后实测间隔约 **0.27s**，且内容逐字（"基于"→"【"→"共享池精选"→"记忆】，"）。

**② SSE 卡死在"调度中"（最隐蔽的一个）**
现象：前端 `reader.read()` 永不返回，按钮一直"调度中…"，但后端日志显示流已发完、`done` 也发了。curl 测却正常。

根因：`BaseHTTPRequestHandler` 默认 `protocol_version = "HTTP/1.0"`，而响应头里发了 `Connection: keep-alive` —— 服务端据此**不关闭 socket**，可它实际也只处理这一个请求，于是浏览器永远等不到流结束。

两端都修了：
- 服务端发完流后 `self.close_connection = True`
- 前端收到 `done`/`error` 立即 `reader.cancel()` 并跳出循环（`ERR_ABORTED` 是预期行为，不是错误）

> 教训：**HTTP/1.0 下不要发 `Connection: keep-alive`**。要么升到 1.1 并保证每个响应有 `Content-Length`，要么老老实实 `close`。

### 验证

```bash
# 真流式判据（delta 到达时间分布）
curl -sN -X POST http://127.0.0.1:8787/api/canvas/ask \
  -H "Content-Type: application/json" \
  -d '{"session_id":"canvas_main","query":"注意力机制怎么用？"}' \
  | while IFS= read -r l; do case "$l" in data:*) echo "$(date +%S.%N) $l";; esac; done \
  | grep delta
```
实测：delta 间隔 ~0.27s，逐字输出 → 真流式成立。
`scripts/shot_all.py` 全站回归：三页零报错。

### 又修了一个布局时序坑

图拓扑默认布局是力导向 `cose`，但 **fit 必须等 `layoutstop` 事件，不能用 `setTimeout`**：
cose 是渐进收敛的，定时 fit 会在它还没停时缩放，导致右侧留白、节点堆在底部。

另外 `cose` 的 `randomize` 要**分首次与重排**：
- 首次 `true` —— 自由展开才能铺成方形；
- 之后 `false` —— 复用当前位置，否则每点一次布局整张图都乱跳。

> 顺带说明：之前"复用 breadthfirst 初始位置再收敛"（`randomize:false`）是个陷阱 ——
> 结果形状跟分层几乎一样，看着像改了参数其实没生效。

## 八、D-056：虚线与箭头错位（涂总现场发现）

### 现象
图拓扑页放大后可见：**虚线在到达节点前就断开，箭头孤立在节点边缘**，两者之间有明显 gap。

![错位修复后](shots/50_zoom_flow.png)

### 根因：Cytoscape 的 dash pattern 不为箭头预留长度

`arrow-scale` 会把线的**终点缩短**给箭头腾位置，但 `line-dash-pattern`
仍按**原路径总长**铺 dash 段。两套长度基准不一致，最后一段 dash 就被错开：

```
线（视觉）  ├───────────◆        ← 终点被 arrow-scale 截短
dash（计算）├───────────────      ← 仍按原长度铺，末端落在箭头之后
```

这是 Cytoscape 的既有行为，不是我们配置写错，但结论一样：**虚线 + 箭头不能共存**。

### 处置：按语义分级，边只有「实线」或「虚线无箭头」两种形态

| 边类型 | 形态 | 理由 |
|---|---|---|
| 常规 typed 边、**选源命中边**（`flow`） | **实线 + 箭头** | 核心视觉，绝不能因样式错位丢信息 |
| `similar_to`（最弱，强度 0.3） | 虚线 + 无箭头 + 40% 透明 | 弱化即可，方向由布局（左→右）表达 |
| 用户从图例隐藏的边 | 虚线 + 无箭头 | 同上 |
| 成环降级（`cycle_rejected`） | 虚线 + 无箭头 | 本来就靠虚线表达"特殊"，不需要箭头 |

### 顺带修掉的第二个问题

原来 `startFlow()` 用逐帧改 `line-dash-offset`（负数）做"流动"：
- `line-dash-offset` 虽是合法属性，但传负数超出 dash 周期长度（`[7,5]` 共 12px），行为不可控；
- 而且**它本身就是错位的放大器** —— dash 相位在动、箭头钉在终点，越动越错。

改为**实线 + 宽度呼吸**（`width` 在 3.6↔6.4 之间按正弦往复，周期 1.4s）。
视觉上读作"这条边正在被选中"，且完全没有箭头冲突。

### 顺带加的调试句柄

`window.__srtpCy = cy` —— 暴露 Cytoscape 实例，
`scripts/shot_zoom.py` 据此按节点真实屏幕坐标裁剪截图。
之前只能盲猜像素裁剪，深链 + 暴露实例是唯一稳定的自动化验证入口。
