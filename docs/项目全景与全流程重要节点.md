## 0. 三分钟理解这个项目

**一句话**：多智能体场景下，主线 Agent 拥有**完整记忆池**，副线 Agent 在**隔离沙箱**里只看到很少的记忆；本项目研究"**该把哪些记忆共享给副线**"——用**四维注意力打分 + LLM 可学习权重**做调度决策，把完整池里最有价值的记忆压缩成 ≤10 条注入副线。

**为什么难**：副线上下文有限（不能给它全量），但给少了它会"失忆"。所以问题本质是**在压缩率约束下最大化记忆增益**——一个带约束的选择问题。

**方法三层**：

| 层 | 做什么 | 关键 |
| --- | --- | --- |
| ① 召回 | 从常驻完整池里捞候选 | 候选集统一 **50 条**（消融常量） |
| ② 打分 | 四维注意力给每条记忆打分 | 时间 / 语义 / 频率 / 任务 |
| ③ 决策 | 混合权重融合 + 阈值选择 | α·LLM先验 + β·可学习 MLP；保留 ≤10 条 |

**最终产物**：一条"完整池 50 条 → 精选 ≤10 条"的调度决策，压缩比 ≤0.3，全链路 <1s。

## 1. 整体架构全景

```
┌─────────────────────────────────────────────────────────────────┐
│                        用户提问 query                              │
└───────────────────────────┬─────────────────────────────────────┘
                            ▼
        ┌───────────────────────────────────────────┐
        │   MemorySchedulingMiddleware（调度总入口）  │  srtp_memory/middleware.py
        │   schedule_once(query)                     │
        └───────────────────┬───────────────────────┘
                            ▼
   ┌────────────────────────────────────────────────────────┐
   │            MemoryCoordinator（协调层，持双池）           │  coordinator.py
   │                                                        │
   │  ① 召回   retriever.recall(query, pool, top_k=50)      │
   │  ② 权重   weights.calculate(query_emb, condition)      │
   │  ③ 打分   scorer.score(...) → 四维分                    │
   │  ④ 选择   selector.select(...) → kept ≤10              │
   │  ⑤ 写池   shared_pool.add() + mark_access()            │
   │  ⑥ 埋点   logger.log_schedule(...)                     │
   └────────────────────────────────────────────────────────┘
          ▲                                    │
          │                                    ▼
   ┌──────┴───────────┐              ┌──────────────────┐
   │ 常驻完整池        │   精选注入    │ 共享池（≤10 条）  │
   │ ResidentMemoryPool│  ──────────▶ │ SharedMemoryPool │
   │ JSONL + faiss 索引│              │ 有序 + 持久化     │
   └──────────────────┘              └────────┬─────────┘
          ▲                                    │ coordinator.dispatch()
          │ 全量只读                            ▼
   ┌──────┴───────────┐              ┌──────────────────┐
   │  主线 MainAgent  │              │ 副线 SubAgent ×N │
   │  （完整上下文）   │              │ （隔离沙箱）      │
   └──────────────────┘              └──────────────────┘
```

**隔离的本质（D3）**：主线与副线不是多进程，而是**逻辑隔离**——各自独立的 Agent 实例 + 独立 workspace 路径 + 独立 session_id。副线**只**能看到 `coordinator.dispatch()` 交给它的共享池内容，看不到常驻池。

## 2. 全流程重要节点（★核心章节）

> 下面按**一次真实问答的时间顺序**走一遍。每个节点给出：做什么 / 输入→输出 / 代码位置 / 关键公式 / 为什么重要。

### 阶段 A：记忆入库（离线/增量）

#### N1. 记忆写入 `add_memory(text)`

| 项 | 内容 |
| --- | --- |
| 位置 | `srtp_memory/middleware.py:133` `add_memory()` |
| 输入→输出 | 文本 → `MemoryCandidate`（含 embedding）→ 写入常驻池 |
| 关键 | **入库即算 embedding 并 upsert 进 faiss 索引**；否则 `retriever.vector` 无语料可检 |
| 副作用 | `resident_pool.upsert()` 同时维护内存 dict + faiss 索引 + JSONL 落盘 |

`MemoryCandidate` 字段（`attention.py:29`）：`memory_id`(uuid) / `text` / `path`+`start_line`+`end_line`（**书签定位用**）/ `timestamp` / `access_count` / `task_tag` / `user_id` / `session_id` / `bm25_score` / `vector_score` / `embedding`。

> ⚠️ 元数据**没有独立的 `memory_meta` 侧表**，全部作为 `resident_pool.jsonl` 每行字段（D-10）。

### 阶段 B：一次调度的 6 步管线（`coordinator.schedule()`，`coordinator.py:73`）

#### N2. Query 向量化

- 位置：`middleware.py:120` `query_emb = self.embedding.encode(query)`
- 模型：DashScope `text-embedding-v4`，**1024 维**（D-5，非 768）
- 落盘缓存：`data/embed_cache/`，保证**实验可复现**（NFR-6）
- 无 key 时自动降级为确定性占位向量，pipeline 不中断（D-11）

#### N3. LLM 先验 → 四维权重（α 侧）

- 位置：`middleware.py:124` `prior = self.weights.llm_prior(query)` → `set_prior(prior)`
- 做什么：让轻量 LLM 直接判断"这次查询该偏重哪几维"，输出 `{"time":…, "semantic":…, "frequency":…, "task":…}`，和=1
- 实现：`weights.py:191` `llm_prior()`，走 `model.deepseek` 单次采样（`llm_prior_samples=1`，预算 ≤800ms）
- **失败兜底**：解析失败/无 key → 回退 `DEFAULT_WEIGHTS`（`{time:0.25, semantic:0.35, frequency:0.15, task:0.25}`）
- **为什么重要**：这是"LLM 先验"的来源，天生 per-query 个性化（LLM 读到的是当前会话上下文）

#### N4. 候选召回（top_k = 50）

- 位置：`coordinator.py:83` `retriever.recall(query, pool, top_k=50)`
- **候选集统一 50 条**（`candidate_override=50`）——消融实验的**控制变量**，保证各组可比
- 5 种检索器（`retriever.py`）：

| 插件名 | 类 | 用途 |
| --- | --- | --- |
| `retriever.full` | `FullRetriever` | 全量（baseline-naive 用，"无融合"对照） |
| `retriever.bm25` | `BM25Retriever` | BM25（中文用 jieba 分词） |
| `retriever.vector` | `VectorRetriever` | faiss ANN 语义向量（**full_ours 用**） |
| `retriever.rrf` | `RRFRetriever` | BM25+向量 RRF 融合 |
| `retriever.reme` | `RemeNativeRetriever` | wrap ReMe 原生 search（baseline-reme 对照） |

#### N5. 混合权重（★创新点 1）

- 位置：`coordinator.py:90` `weights.calculate(query_emb, cond)`；实现 `weights.py:179`
- 公式：

```
hybrid = α · prior(LLM先验)  +  β · learnable(MLP)
        α=0.6                    β=0.4        归一化后输出
```

- 可学习侧：`_ConditionedMLP`（`weights.py:32`）

```
输入 = query_emb(1024, L2归一化) ⊕ condition_emb(32)
     → Linear(1056 → 64) → ReLU → Linear(64 → 4) → Softmax → 四维权重
```

- **条件化个性化**：`conditioning_dims = ("semantic", "task")`——只有这两维随 user/scenario/business 漂移，time/frequency 保持全局（避免冷启动与过拟合）
- **两阶段学习**：
  - 阶段一（离线蒸馏）`pretrain_distill()`：MSE 损失，目标 = LLM 先验权重（多次采样平均）
  - 阶段二（在线反馈）`update_with_feedback(reward)`：reward ∈ {+1 赞 / -1 踩}，bandit 式一步更新，target = `cur × (1 + 0.1·reward)`
- **为什么重要**：α 保证"LLM 先验保底"不崩，β 让系统能从真实反馈中越用越准；α/β **V1 固定不学习**，保证消融归因干净

#### N6. 四维打分（★创新点 2）

- 位置：`coordinator.py:97` `scorer.score(...)`；实现 `attention.py:54`
- 四个头（`attention.py:79-106`）：

| 维度 | 公式 | 直觉 |
| --- | --- | --- |
| **时间** `time` | `exp(-λ·t)`，λ=0.01/小时 | 越新越重要，指数衰减 |
| **语义** `semantic` | `0.5·cosine + 0.3·vector_score + 0.2·bm25_score` | 与 query 的相关性（三路信号融合） |
| **频率** `frequency` | `1 - exp(-0.1·access_count)` | 被用得越多越重要（饱和增长） |
| **任务** `task` | 标签匹配 1.0 / 不匹配 0.3 / 双方空 0.5 | 同任务标签优先 |

- **语义头内部系数** `W_COS, W_VEC, W_BM25 = 0.5, 0.3, 0.2` ——注意这与全局 α/β **完全无关**，别混淆
- `enabled_dims` 掩码：关掉的维权重置 0，其余**重新归一化保持 Σ=1**（用于 `+attention` 消融逐维验证，REQ-610）

#### N7. 加权融合 → final 分

- 位置：`coordinator.py:98`

```
final = Σ_d ( w_d · s_d ) / Σ_d w_d          d ∈ {time, semantic, frequency, task}
```

分母用**有效权重之和**（而非 1），保证关闭部分维度后分数仍在可比区间。

#### N8. 动作选择（保留 ≤10 条）

- 位置：`coordinator.py:104` `selector.select()`；实现 `selector.py:19`
- **自适应阈值**：`thr = max(threshold, mean - 0.5·std)`（threshold=0.6）—— 避免候选整体偏低时"全丢"或整体偏高时"全留"
- `kept` 按 final 降序、截断 `max_shared=10`
- **压缩比** = `kept / (kept + discarded)`，验收目标 **≤0.3**

#### N9. 写共享池 + 频率回写

- 位置：`coordinator.py:112-119`
- `shared_pool.add({memory_id, text, path, start_line, end_line, score, timestamp})`：按分数**有序插入**，超 10 条丢最低分
- `resident_pool.mark_access(memory_id)`：**访问次数 +1** → 影响下一次的 frequency 头（形成闭环）
- 共享池设计要点：**没有 `query()` 方法**——副线吃 `top()` 全量精选集，**不做二次检索**（保持"排序/选择是唯一变量"这一消融常量）

#### N10. 埋点落盘

- 位置：`coordinator.py:125` `logger.log_schedule(res.to_dict())`
- 落盘：`data/metrics/schedule.jsonl`（L3 层）
- 每条含：`query / task_tag / condition_key / weights / candidate_count / kept_count / discarded_count / compression_ratio / latency_ms / enabled_dims`
- **这是所有消融指标的原始数据源**

#### N11. 副线注入 `dispatch()`

- 位置：`coordinator.py:128` `dispatch(sub_agent, top_k=10)`

#### N12. 真实 AgentScope 执行

- 位置：`srtp_memory/agentscope_runtime.py`（2026-08-27 落地）
- 主线 + 两条副线（sub1 检索副线 / reviewer 校验副线）均为**真实 AgentScope 2.0.6 `Agent` 实例**
- 装配：`DeepSeekChatModel(credential=DeepSeekCredential(api_key), model="deepseek-v4-flash")`
- 调用：`asyncio.run(agent.reply(UserMsg(name="User", content=...)))`（**不能** `agent(msg)` 直接调用）
- **工具系统**：`Toolkit([Read, Write, Edit, Glob, Grep, Bash])` + `BYPASS` 权限 → 智能体可真实读写文件、执行命令
- 降级：缺 agentscope 或缺 key → headless（仍是真实 embedding + LLM，页面标注 `agent_mode`）
- 详细 API 与坑点见 [AgentScope与ReMe学习指南 §8](AgentScope与ReMe学习指南.md)

#### N13. 反馈闭环（在线学习）

- 位置：`weights.py:278` `update_with_feedback(query_emb, reward, condition)`
- reward ∈ {+1 点赞 / -1 点踩}，bandit 式一步更新**β 侧 MLP 参数**
- 受 REQ-405 正则化约束：更新后向 LLM 先验回归，防止学偏
- **注意**：α/β 融合系数与 LLM 本身**不参与更新**——这是刻意设计，保证消融归因干净

## 3. 关键设计决策速查

| 编号 | 决策 | 为什么 |
| --- | --- | --- |
| D-3 | 本地单机单进程，隔离靠**逻辑**隔离（独立实例+双池+session_id） | 多智能体 ≠ 多进程；V1 保持简单 |
| D-5 | embedding 用 DashScope **1024 维**（非 BERT 768） | 外部 API 实际决策，论文称"替代 BERT 的轻量向量化" |
| D-9 | 记忆检索**只有一个入口**（调度管线），ReMe 只写回 | 杜绝双份记忆注入与 Token 浪费 |
| D-10 | 无 `memory_meta` 侧表，元数据直接进 `resident_pool.jsonl` | 少一层，避免不一致 |
| D-11 | 真实 API 失败自动降级（占位向量 / DEFAULT_WEIGHTS） | 离线与测试不触发网络、pipeline 不中断 |
| D-12 | ReMe 检索算法**中性化**（只用其 bm25/vector 原始分，不叠加 RRF/wikilink） | 否则无法归因（"提升"来自谁？） |
| D-13 | LLM 先验用**轻量小模型单次采样** | 满足 NFR-1 全链路 <1s |
| — | α/β **固定不学习** | 保 LLM 先验保底 + 消融归因干净 |
| — | 候选集固定 50、共享池固定 ≤10 | 消融控制变量 |
| — | 共享池**不做二次检索** | 让"排序/选择"成为唯一变量 |

## 5. 消融实验：5 组与归因链

配置即组合（config-as-composition），5 份 YAML 在 `config/ablation/`：

| 组 | retriever | attention | weight | selector | 含义 |
| --- | --- | --- | --- | --- | --- |
| `baseline_naive` | `full` | `noop` | `uniform` | `topk` | 全量传输、无打分无权重（下界） |
| `baseline_reme` | `reme` | `noop` | `uniform` | `topk` | 纯 ReMe 原生对照 |
| `+attention` | `bm25` | **`full`** | `uniform` | `topk` | 只加四维打分 |
| `+weight` | `bm25` | `full` | **`full`** | `topk` | 再加混合权重 |
| `full_ours` | **`vector`** | `full` | `full` | **`full`** | 完整方案（语义检索+阈值选择） |

**归因链**：`baseline_naive` → `+attention`（四维打分的增益）→ `+weight`（混合权重的增益）→ `full_ours`（检索器与选择器的增益）。每一组只改一个变量，指标提升可逐段归因。

**关键验收指标**（主文档 §2.4）：记忆池压缩比 ≤0.3；NFR-1 全链路 <1s（打分 <10ms/条、MLP <20ms）；6 项指标相对 `baseline-naive` 计算提升。

运行：

```bash
python main.py --ablation                      # 跑 5 组
python analysis/compute_metrics.py             # 算指标
```

## 7. 易混淆点（FAQ）

**Q：四维"注意力"和向量维度 1024 有关系吗？**
A：完全无关。四维是**打分维度**（time/semantic/frequency/task）；1024 是 **embedding 向量维度**，只在语义头的余弦相似度里用到。

**Q：α/β 和 W_COS/W_VEC/W_BM25 是一回事吗？**
A：不是。α/β 是**全局**的"LLM先验 vs 可学习"融合系数（0.6/0.4）；W_COS/W_VEC/W_BM25 是**语义头内部**三路信号的融合系数（0.5/0.3/0.2），两者互不干涉。

**Q：副线"隔离"是真的隔离吗？**
A：是**逻辑隔离**（D3）：独立 Agent 实例 + 独立 workspace 路径 + 独立 session_id，副线只能看到 `dispatch()` 注入的 ≤10 条。V1 不追求进程级/容器级隔离。

**Q：为什么共享池不做二次检索？**
A：一旦副线再检索一次，"最终效果"就同时受调度和副线检索影响，消融实验无法归因。共享池吃 `top()` 全量，让"排序/选择"成为**唯一变量**。

**Q：控制台里共享池有些点是空心的？**
A：那是**历史留存**记忆——上一轮保留进池、本轮没再被选中。绿实心+动画连线才是**本轮真正调度**的。这个区分是刻意做的，避免误读。

**Q：改了配置没生效？**
A：检查 `config/srtp.yaml` 的 `*_impl` 字段；插件是在 `middleware.__init__` 里**一次性装配**的，改配置要重启进程。消融实验改 `config/ablation/*.yaml` 并重新运行。
