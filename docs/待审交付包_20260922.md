## 2. 八条发现

1. **★核心主张成立**：G4 相对 G2（单源=主副线等价物）recall 与源覆盖**各 +13.5pt**。
   G2 的 `src_hit=0.8654` 说明近 13.5% 的查询**漏掉了应当参考的上游模块** —— 一对一筛选的结构性缺陷。
2. **❌ 算法层没跑赢"不调度"下界**：G0(0.9808)/G1(0.9615) 高于 G3/G4(0.9423)，`G4−G1 = −1.92%`。
   → **"提升来自算法"当前不成立**；论文口径只能是"图提供结构先验"。与 POC 第二轮"G1 写入序最高"同源。
3. **❌ G4 ≡ G3**：边强度配额不起作用。K=4 探针复现（两组仍一致）。
   根因（结构性非 bug）：每源池仅 4 条 < 单源配额 → 硬配额退化为"全取"；且自适应阈值才是真正裁决者。
   → 需"源池条目数 ≫ 单源配额"的数据集才能检验。
4. **✅ 自动选源已达人工（oracle）上界**（Q7 答案）：G4 与 G4-oracle 完全一致。算法不需要人工选源。
5. **✅ 多源确实发生**：多源样本 `multi_source_ratio = 0.381 > 0.3`。
   （全样本均值 0.119 是口径问题——19/26 条本身是单源问题，该值必然 0 → 已改口径。）
6. **✅ 速度余量极大**：全组 p90 ≤ 2.4ms（已预热 query embedding，不含网络），NFR-1 有 ~400× 余量。
   但压缩比 0.75 未达 ≤0.3（邻域本身只有 ~5 条候选）。
7. **⚠️ 均衡档 B0–B4 全部不可辨识**：三原因都是环境/规模问题——① LLM 先验是无 key 的空调用；
   ② 候选池 <20 故截断不生效；③ 源数 ≤3 故 λ 无差别。
8. **✅ 度量口径三处修正**：① `multi_source_ratio` 只在多源样本上平均；
   ② 延迟必须预热 embedding 后测（第一版 G2 p90=368ms 全部来自"谁先跑网络"）；
   ③ `dedup_rate` 在 `owner_node` 单值标记下**结构性恒为 0**（保留指标但不得作证据）。
