# 验收标准：做到什么算合格，做到什么算结束

> **本文定位**：把"发 EI 论文 + 开源产品"这个目标，拆成**可勾选的验收项**。
> 每一项都能用"是 / 否"回答，不接受"差不多""基本完成"。
> 最后更新：2026-10-08

---

## 0. 目标定义（三件事，缺一不可）

| 目标 | 一句话合格标准 |
|---|---|
| **研究成果** | 有一个**可被验证**的主张，且有实验支撑（不是"跑通了"，是"证明了"） |
| **EI 论文** | 论文被 EI Compendex 收录的会议/期刊接收 |
| **开源产品** | 陌生人能**独立** clone → 装 → 跑 → 复现，不需要问作者 |

## 1. 现实差距：三个硬伤（已核实，不是推测）

2026-10-08 全仓库核查结果：

| 缺口 | 核查证据 | 后果 |
|---|---|---|
| **自造数据集自评** | 50 episodes 全部合成；`analysis/` 无任何公开数据集引用 | 结论只对自建图成立，审稿必问 |
| **零外部基线对比** | 全仓库 grep `LoCoMo\|MSC\|LongMemEval\|MemGPT\|A-MEM\|MemoryBank` = **0 命中** | 无法证明优于已有方法 |
| **零统计显著性** | grep `significance\|p_value\|t-test\|bootstrap` = **0 命中** | 0.83 vs 0.80 无法区分于噪声 |

开源侧硬门槛：

| 项 | 状态 |
|---|---|
| LICENSE | ❌ **没有**（法律上别人不能用） |
| CI（GitHub Actions） | ❌ 没有 |
| `pyproject.toml` / `setup.py` | ❌ 没有（无法 pip install） |
| README | ⚠️ 仅 92 行 |

| 测试 | ✅ 84 passed（2026-10-07 实测） |

**判断**：系统本身已经够格，**缺的是"实验可信度"和"开源合规"**。
算法层面不需要再发明新东西，需要的是**把已有的东西证明给别人看**。

## 2. 实验线（生死线，最优先）

### 2.1 数据与基线

- [ ] **D1** 确定评估数据集（**二选一，或双轨**）
  - [ ] 方案 A：公开数据集（LoCoMo / LongMemEval / MSC 之一）—— 需先探网络可达性
  - [ ] 方案 B：自建真实多轮数据集（AgentScope + DeepSeek 真实跑，扩大 POC 第二轮的 6 节点/47 记忆规模）
  - [ ] 若走方案 B：数据集本身作为贡献写进论文（"我们构建了多智能体记忆共享场景数据集"）
- [ ] **D2** 实现多轮会话评估器（**与 D1 合并做**）
  - [ ] 同一 middleware 实例按序回放会话查询
  - [ ] 状态跨查询延续（记忆池、access_count、边 interactions、MLP 权重）
  - [ ] 中途可注入真实反馈（点赞/点踩）
  - [ ] **这是检验 ②b 条件化 / ②c 反馈闭环的唯一途径**
- [ ] **D3** 至少两个外部基线对比
  - [ ] 传统检索基线：BM25、纯向量检索（仓库已有 `retriever.*`，可直接用）
  - [ ] 记忆系统基线：复现一个已有方法的核心思路（如 MemoryBank 的遗忘曲线 / A-MEM 的动态索引）
  - [ ] 基线必须在**同一数据集、同一 K、同一指标**下跑，否则不可比
- [ ] **D4** 统计显著性
  - [ ] 每个对比报 p 值（配对 t 检验或 Wilcoxon）
  - [ ] 报置信区间（bootstrap，≥1000 次重采样）
  - [ ] 明确标注哪些差异**不显著**（不能只报赢的）

### 2.2 可复现性

- [ ] **D5** `run_manifest` 完整（随机种子、依赖版本、embedding 缓存哈希、配置快照）
- [ ] **D6** 一键复现脚本（`scripts/reproduce.sh` 或 `.py`），新机器上跑完能对齐论文表格
- [ ] **D7** 数据集与评估脚本随论文一起公开

### 2.3 诚实边界（写进论文的表述纪律）

- [ ] **D8** 五个创新点按证据等级分别表述，不得拔高：

| 创新点 | 允许的表述 | 禁止的表述 |
|---|---|---|
| ① 图多对多 > 单源 | "实验证明"（合成数据已证，真实数据待补） | — |
| ②a 四维注意力 | "在硬约束场景有效"（S-A/S-B MRR 1.0） | "全面提升排序精度" |
| ②b 条件化个性化 | "机制验证通过" | "端到端效果显著" |
| ②c 反馈闭环 | "机制验证通过" | "端到端效果显著" |
| ②d 强度配额 | "机制正确，适用边界为 X" | "优于均匀配额" |

- [ ] **D9** 报天花板 `ceiling = min(1, K/|relevant|)`，不得用宽松 ground truth 制造假象
- [ ] **D10** 成本/开销表：三档 (效果 E, 成本 C, 延迟 T) 的 Pareto 取点，
      **不主张** 自编的 `J = E − γC·C − γT·T` 是可优化目标

## 6. 风险预案（必须提前想好）

### 风险 1：真实数据集上我们没有优势

**这是最可能发生的风险。** 合成数据上的梯度是我自己设计的场景造出来的，真实数据上不一定成立。

预案（**不允许**的方向：改数据、调 ground truth、只报赢的结果）：

- **A. 换主张**：从"我们的方法全面更好"改为"我们的方法在**硬约束场景**（版本消歧、口径隔离）显著更好，在纯语义场景与基线持平"。
  这是**诚实且有价值的结论**——S-A/S-B 的 MRR 1.0 是真实优势。
- **B. 转分析型论文**：把"配额/带宽不是瓶颈，源内排序才是"（D-039 结论）作为**主要贡献**，
  这是一条经过四轮验证的机制认知，本身就是研究产出。
- **C. 补场景**：如果真实数据上劣势集中在某一类查询，就把它作为**适用边界**写进论文。

### 风险 2：公开数据集下载不了（国内网络）

预案：走方案 B 自建数据集，并把"数据集构建方法"作为贡献之一。
POC 第二轮已经跑通过（6 节点/7 边/47 记忆），有基础。

### 风险 3：API 成本与时间

自建真实数据集要真实调用 LLM 生成多轮会话。
预案：先小批量（10 会话）验证流程，再决定是否扩大；embedding 走落盘缓存（已有机制）。

### 风险 4：时间不够

如果时间紧，**保论文的实验可信度，砍产品打磨**。
产品侧最低限度：LICENSE + README + 能跑通 = 已算开源（O1、O6、O7）。
CI、文档收敛、演示 GIF 都可以后置。

## 7. 结束的判定（Definition of Done）

**全部满足才算结束：**

1. ✅ 论文被 EI 收录的会议/期刊**接收**（不是"投出去"）
2. ✅ 仓库公开，且有 LICENSE，陌生人能独立 clone → install → run → reproduce
3. ✅ 论文中的每个数字都能用仓库里的脚本**重新跑出来**
4. ✅ 所有创新点的表述与证据等级**一致**（没有拔高、没有隐藏负面结果）
5. ✅ 声明的局限都写进了论文（②d 适用边界、E3/E4 端到端未证、S-C 短板）

**其中第 4、5 条是底线**——这两条破了，前面三条做得再漂亮也不算合格。
