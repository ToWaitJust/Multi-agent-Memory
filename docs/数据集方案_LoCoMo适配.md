## 2. 为什么是 LoCoMo

候选对比（2026-10-08 实测可达性）：

| 数据集 | 可达性 | 规模 | 与本系统的匹配 |
|---|---|---|---|
| **LoCoMo**（ACL 2024, Snap Research） | ✅ GitHub 直取 2.7MB | 10 对话 / 272 session / 2541 事实 / 1986 QA | **结构同构** |
| LongMemEval（ICLR 2025） | ⚠️ HuggingFace 需代理，s 版 277MB | 500 QA / ~48 session each | 也合适，但下载重 |
| MSC（Meta） | 未测 | 多会话闲聊 | session 偏短 |

**直连实测**：GitHub / HuggingFace **直连均超时（000）**；
`socks5h://127.0.0.1:3067` 代理可用（200）。LoCoMo 走代理下载成功。

### 结构同构是决定性因素

| LoCoMo 概念 | 本系统概念 | 说明 |
|---|---|---|
| `session_k`（一次会话） | **topic 图节点** `TopicNode` | 节点=会话，正是我们的定义 |
| `observation` 中每条事实 | **记忆条目** `MemoryCandidate` | 2541 条现成的记忆语料 |
| 事实自带的 `dia_id` | `owner_node` 标记 | 零成本打标 |
| `qa.evidence`（dia_id 列表） | **relevant（memory 级 ground truth）** | ★ 不需要人工标注，不需要猜 |
| `qa.category`（1~5） | `scene`（分层维度） | 天然的分场景分析 |

**最关键的一点**：`evidence` 给的是 `dia_id`，而每条 observation 事实**自带 dia_id**，
两条一 join 就得到 **memory 级的 ground truth**。这是别的数据集给不了的。

## 3. 数据规模

```
对话 10 个 ｜ session 272 个 ｜ observation 事实 2541 条 ｜ QA 1986 条
平均每 session 9.3 条记忆 ｜ 平均每对话 254 条记忆
```

对比现有合成数据集（22 节点 / 490 记忆 / 50 episodes）：**规模提升一个数量级**。

### QA 分层（category，由跨源率实测确认映射）

| cat | 含义 | 数量 | 跨 session 比例 | 对本课题的意义 |
|---|---|---|---|---|
| 1 | **multi-hop** | 282 | **95.4%** | ★ **主战场**：答案分散在多个 session，正是多源选源要解决的 |
| 2 | temporal | 321 | 8.7% | 考时间维 |
| 3 | open-domain | 96 | 32.3% | 常识/偏好 |
| 4 | single-hop | 841 | 0.2% | 答案在一个 session 内 → 我们应**持平**，是诚实的适用边界 |
| 5 | adversarial | 446 | 0%（无 answer 字段） | 不可回答，无 ground truth，评估时跳过 |

**跨源（evidence 命中 ≥2 个 session）QA 共 330 条，其中 269 条集中在 multi-hop 类。**

这构成了一个诚实且有说服力的实验设计：
> **在需要跨会话聚合的问题上，多源选源显著优于单源/纯语义；
> 在单会话问题上与基线持平 —— 这正是方法的适用边界。**

## 4. 映射实现（`analysis/locomo_adapter.py`）

```bash
# 单对话（跑通验证用）
python -m analysis.locomo_adapter --conv 0 --stats-only
python -m analysis.locomo_adapter --conv 0

# 全量 10 对话
python -m analysis.locomo_adapter --conv all --out data/locomo_all.jsonl
```

### 关键设计决策

| 决策 | 选择 | 理由 |
|---|---|---|
| **cur_node** | 该对话的**最后**一个 session | 模拟"对话进行到现在，问这个问题"，答案在历史任意 session |
| **记忆条目** | `observation[session][speaker]` 的每条 `[text, dia_id]` | 现成的事实级记忆，带溯源 |
| **relevant** | `evidence` 的 dia_id → memory_id（**精确命中**） | 最严格、最可辩护；不做宽松扩展 |
| **边方向** | 早期 session → 晚期 session | 符合"被依赖方 → 依赖方"的边语义 |
| **建边方式** | 每 session 向更早的 session 按 Jaccard 相似度取 top-3 | 方向由时序保证，强度由相似度分档 |
| **adversarial** | 跳过（无 evidence） | 无 ground truth 无法评估召回 |

### 一个必须讲清的问题：平均 |relevant| = 1.19

LoCoMo 的答案通常落在一句话里，所以 evidence 常只有 1 个 dia_id。
这看起来像 D-043 踩过的坑（|relevant| 太小 → recall 只有 {0,1} 两档）。

**但这里不致命，因为主指标是 MRR**：

- `recall@K` 在 |relevant|=1 时确实是二值 {0,1}；
- **MRR = 1/rank，rank 可以是 1~K，有 K 档分辨力**；
- 天花板 `ceiling = min(1, K/|relevant|) = min(1, 5/1) = 1`，不产生假象。

所以：**K 设 5（给 rank 空间），主指标 MRR/nDCG，recall 作二值辅助**。
这正是 D-043 那条方法论（"排序器用 MRR/nDCG"）在真实数据集上的兑现。

## 5. 已验证结果（conv0 **全量 155 episodes**，K=5，真实 DashScope embedding）

| 组 | recall | **MRR** | nDCG | multi_src |
|---|---|---|---|---|
| G0/G1 邻域全量（无算法） | ≈0.198 | — | — | — |
| **G2 单源** | **0.0677** | **0.0581** | 0.0583 | 0.00 |
| G3 多源 + 均匀配额 | 0.2271 | 0.2018 | 0.2018 | 0.41 |
| G4 多源 + 强度配额 | 0.2303 | 0.2018 | 0.2033 | 0.41 |
| **G4_qs_w（+过滤 +配额约束）** | **0.2432** | **0.2133** | 0.2147 | **0.60** |

### 成立的（好消息）

✅ **G4 >> G2**：recall **+16.3pt**、source_hit **+20.7pt**（判据 PASS）。
**核心主张（多对多 > 一对一）在真实公开数据集上强成立**——
比合成数据上的 +3.7pt 强得多，因为 LoCoMo 的答案天然分散在多个 session。

✅ **G4_qs_w 是最优组**（recall 0.2432 / MRR 0.2133），且在 **multi_hop 子集上提升最大**：

| multi_hop 子集（n=28） | recall | MRR |
|---|---|---|
| G3 / G4 | 0.1321 | 0.1577 |
| **G4_qs_w** | **0.2036** | **0.1708** |

→ **过滤 + 配额约束在跨源场景上 +7.1pt recall**，且 multi_src 从 0.41 升到 0.60。

这是本次接入**最有价值的成果**：核心主张第一次有了真实数据集的支撑，
而且最优组的优势**恰好集中在我们的目标场景（跨会话聚合）**上。

### 不成立的（必须诚实报告）

| 现象 | 数值 | 说明 |
|---|---|---|
| ❌ G4 − G1 = 0.0322 | 判据要求 ≥0.05 | 四维加权融合相比"无算法"增益不足 |
| ❌ G4 − G3 = 0.0 | 完全相同 | 强度配额与均匀配额无差异（老问题复现） |
| ❌ G1 − G0 = 0.0 | — | 需查 G0/G1 是否退化为同一路径 |
| ❌ G4_norm < G4 | MRR 0.1303 < 0.2028 | **批级归一化在真实数据上有害**（推翻预判） |
| ⚠️ 禁用 time 维结果不变 | 与 G4 逐位相同 | 需诊断：time 维为何对排序零影响 |

### 怎么解读（诚实版本）

这**不是坏消息**，而是 D-039 结论在真实数据上的印证：

> **瓶颈不是带宽分配（配额），而是源内排序；
> 当语料语义足够干净时（LoCoMo 的 observation 每句一个独立事实），
> 纯语义排序已接近最优，任何加权融合都是稀释。**

但注意 **G4_qs_w 是例外**：它靠的是**硬约束过滤 + 配额约束**，
而不是加权融合——这恰恰再次印证"多维约束要用过滤，不用打分"这条方法论。

方法在真实数据上的**适用边界**因此清晰了：
价值在于**跨会话聚合**（G4 >> G2，且在 multi_hop 子集上最优），
而不是"在语义已够好时提升排序精度"。

这个叙事**可以写进论文**，而且比"我们全面更好"更可信。

## 5.5 两异常诊断结论（D-050，已闭环）

> 第 5 节留下两个待诊断异常：① 禁用 time 维后结果与 G4 **逐位相同**；
> ② G4_norm 比 G4 **更差**（MRR 0.1303 < 0.2018）。
> 本节给出根因、修复与验证结果。**两个异常是同一个根因**。

### 根因：时间尺度与语料跨度不匹配（一个数量级的错配）

`LAMBDA_TIME = 0.01 / 小时` 的半衰期约 **69 小时（≈2.9 天）**。
而 LoCoMo conv0 的语料跨度是 **432 小时（18 天）**。于是候选记忆的 time 分
被整体压进一个**极窄区间**（`diag_locomo_dims.py` 实测）：

```
time ∈ [0.0215, 0.0561]   std = 0.0168   只有 3 个不同取值
```

这造成两个**方向相反但同源**的失败：

| 处理 | 后果 | 实测 |
|---|---|---|
| 不归一化 | time 几乎是常数 → 白占 0.25 权重，但对排序零影响 | 禁用与否**逐位相同**（异常①） |
| 批内 min-max | 噪声被拉伸到满量程 [0,1]，**放大约 28 倍** → 反客为主 | G4_norm MRR **0.1303 < 0.2018**（异常②） |

且 min-max 后 time 偏向"时间上更新"的记忆，而**长期对话里答案往往在早期 session**
（问题问的是过去的事）——方向本身就是反的。

### 修复（两个新打分器，原实现全部保留作对照）

| 插件 | 时间尺度 | 无效维门控 | min-max |
|---|---|---|---|
| `attention.full`（原） | 固定 λ | ✗ | ✗ |
| `attention.normalized`（原） | 固定 λ | ✓ | ✓ **（放大噪声）** |
| `attention.adaptive_time`（新） | **自适应 λ** | ✗ | ✗ |
| `attention.adaptive_gated`（新） | **自适应 λ** | ✓ | ✗ |

自适应尺度：`λ_eff = TIME_DECAY_K / span_hours`（span_hours = 候选集时间戳跨度）。
无论语料跨小时、跨天还是跨月，time 分在候选集内始终跨越 `exp(-K) → 1.0`
的完整动态范围（K=2 时约 [0.135, 1.0]）。

### 验证结果（conv0 全量 155 episodes，K=5，真实 embedding）

| 组 | recall | **MRR** | nDCG | 相对 G4 |
|---|---|---|---|---|
| G4（`full`，基线） | 0.2303 | 0.2018 | 0.2033 | — |
| **G4_adt**（自适应 λ） | 0.2303 | **0.2115** | **0.2097** | MRR **+0.97pt** |
| G4_adt_gate（+常量维门控） | 0.2239 | 0.1972 | 0.1971 | MRR −0.46pt |
| G4_norm（固定 λ + min-max） | — | 0.1303 | — | MRR −7.15pt |
| **G4_semonly**（只留 semantic） | 0.2303 | 0.2008 | 0.2025 | MRR −0.10pt |

### 决定性发现：G4 事实上就是纯语义

`G4_semonly` 与 `G4` 的 **recall 逐位相同**（总体 0.2303，且五个 scene 分项
0.2571 / 0.1321 / 0.2727 / 0.2826 / 0.2000 **全部一致**），MRR 只差 0.001（噪声级）。

→ **在 LoCoMo 上，time / frequency / task 三维对 top-K 选择零贡献，
四维注意力退化成了纯语义。** 原因逐条定位：

| 维 | 状态 | 原因 |
|---|---|---|
| `task` | ≡ 1.0 | 语料没有"口径"概念，所有候选与 query 同标签（白占 0.25） |
| `frequency` | ≡ 0 | 首轮 `access_count = 0` → `1-exp(0) = 0`（白占 0.15） |
| `time` | 修复后仍≈0 贡献 | 长期对话里 recency 与相关性近乎正交（甚至反向） |

**合计一半的权重预算被无效维吃掉**，语义维实际只拿到 0.35/1.0。

### 门控为什么反而更差（一个反直觉的负面结果）

`G4_adt_gate` 门控掉了 task/frequency，把回收的权重**按原比例分给了 time 和 semantic**
→ time 权重从 0.25 涨到 **0.417** → 而 time 在 LoCoMo 上是无效甚至有害的 → 变差。

**这说明门控判据本身有缺陷**：现有判据是"批内标准差 > 0"，只能识别
"**有没有区分度**"，不能识别"**有没有用**"。自适应 λ 之后 time 有了区分度，
于是被判为有效维并拿到更多权重——但它与相关性无关。

→ 识别"有区分度但无相关性"的维，**超出了纯批内统计的能力**，
需要反馈信号（E4）或外部先验。这为 E4 反馈机制的必要性提供了直接证据。

### 对论文的直接影响（叙事重构）

这个负面结果其实**强化了核心主张**，而不是削弱：

> 在 LoCoMo 上的全部增益（G2 → G4，recall +16.3pt）**来自图结构与多源配额**，
> 四维注意力贡献为零。这把"跨智能体记忆共享调度"这一创新点从
> "四维打分 + 多源"里**干净地剥离**出来——创新点唯一，归因干净。

必须诚实写进论文的三条：

1. **四维注意力的有效性依赖语料是否提供对应信号**（task 标签 / 访问史 / 短跨度 recency）。
   LoCoMo 三者皆无 → 退化为纯语义。合成数据上有效（S-A/S-B MRR 1.0）正是因为提供了这些信号。
2. **固定 λ 的指数衰减在长跨度语料上结构性失效**，自适应 λ 是必要修正（MRR +0.97pt，
   recall 不变 → 只改善 top-K 内位次，不影响命中集合）。
3. **min-max 归一化会放大无效维**，门控比归一化更重要，但门控判据需升级。

⚠️ 上述 Δ 目前**均未做显著性检验**（见第 6 节）。MRR +0.97pt 是否真实仍需 bootstrap 确认。

## 5.6 真正的瓶颈：Stage A 选源可达性（D-051，oracle 实测）

> 起因是"四维注意力要不要重构"的讨论。在设计 learning-to-rank 的标注可行性时，
> 顺手跑了一次 **oracle 选源**（`--with-oracle`，人工指定正确源），结果推翻了问题排序。

### oracle 上界 vs 实际

| 指标 | G4 实际 | **oracle 选源** | 比值 |
|---|---|---|---|
| recall | 0.2303 | **0.9029** | 3.9× |
| MRR | 0.2005 | **0.7669** | 3.8× |
| cand_hit（相关记忆进候选的比例） | 0.2680 | 0.9974 | 3.7× |
| source_hit（相关源被选中的比例） | 0.2744 | 0.9974 | 3.6× |

### 量级对比（决定一切优先级）

```
选源（Stage A）可提升空间  =  0.9029 − 0.2303  =  0.6726
排序（Stage B）天花板      =  0.2680 − 0.2303  =  0.0377   ← 只有 1/18
```

**排序再怎么优化（四维重构、redundancy、learning-to-rank），
天花板也只是把 recall 从 0.2303 提到 0.2680。**

### 根因实锤：邻域恒为 3，`src_score` 从未参与选择

`analysis/locomo_adapter.py` 建边时每个节点只连 **Jaccard top-3**，
导致 **cur_node 的入边邻居数恒为 3**（min = max = mean = 3.00）。
而 `source_topk = 3` → **三个全选** → 于是：

| 改了什么 | src_hit | 结论 |
|---|---|---|
| `quota_lambda` 0.7 → 0.3 → 0.0 | 恒 0.2744 | λ 无效 |
| `source_topk` 3 → 8 | 恒 0.2744 | 邻域就这么大 |
| `rel_var_threshold` 0.02 → 0.0 | 恒 0.2744 | 不是方差退化的锅 |

且 **相关源落在 depth=1 入边邻域内的只有 30.3%（47/155）**
—— `cur_node` 取的是最后一个 session，而答案分散在早期 session，一步入边够不着。

### ⚠️ 对既有结论的冲击（必须诚实重验）

**G4 − G2 = +16.3pt 是在"邻域恒为 3、全选"的设定下测出来的。**
该设定下 `src_score` 从未真正参与选择，所以这个对比
**只测了"多选 vs 单选"，没有测"选得准不准"**。

→ 邻域修复后，**核心主张必须重验**。这是 D-051 最重要的一条警示。

### 优先级因此改写

1. **修 Stage A 选源可达性**（空间 0.6726）—— 最高优先级
   候选手段：建边加宽（top-3 → top-8/混合语义）、邻域双向、depth=2、
   多跳扩散 / 查询感知自适应扩展
2. **再谈排序层重构**（四维 / redundancy / ltr）
   注意：修好 Stage A 会**解锁**排序的价值——候选里相关记忆变多，才需要排序来挑
3. 显著性检验跟着**修复后**的最终方法一起做

## 5.7 修复与重验（D-052）：语义源扩展 + λ 解锁

### 又一个"看起来在算、其实没生效"的坑：档位把 λ 锁死了

上一节说"λ 怎么调都不动"，根因不止邻域恒为 3，还有第二层：

```python
TIER_SPEC = {
    "full":     {"llm_prior": "call", "candidate": 50, "lambda": 0.7},
    "balanced": {"llm_prior": "cache","candidate": 30, "lambda": 0.7},
    "fast":     {"llm_prior": "off",  "candidate": 20, "lambda": 1.0},   # ★ λ 被硬编码成 1.0
}
```

**fast 档把 λ 强制成 1.0（纯静态选源）**，而所有排查都用 `--tier fast` 跑，
于是 `quota_lambda` 配成 0.0/0.3 全被覆盖。所以此前"λ 无效"的结论是**错的**——
不是 λ 没用，是档位没让它生效。绕开方式：`budget.force_lambda`。

### 修复：语义源扩展（`graph.semantic_source_topk`）

候选源池从「图邻域」扩展为「**图邻域 ∪ 语义 top-N**」：

```python
src_score = λ · strength + (1 − λ) · cos(emb(topic_i), emb(q))
```

语义近邻 **strength = 0**（无图边），只靠 relevance 竞争，不篡改边强度语义。
默认 `semantic_source_topk = 0`（关闭），保证既有消融结论可复现。

配套两处修：`rel_var_threshold` 的方差阈值（余弦方差天然在 0.001~0.01 量级，
默认 0.02 **必然**触发退化）、`SourceSelection.semantic_expanded` 埋点。

### 效果（conv0 全量 155 episodes，K=5）

| 组 | recall | MRR | src_hit | cand_hit |
|---|---|---|---|---|
| G4 基线 | 0.2206 | 0.2005 | 0.2744 | 0.2680 |
| G4 + 语义扩展（λ=0.3） | 0.3647 | 0.3026 | 0.4292 | — |
| **G4 + 语义扩展（λ=0.0）** | **0.4532** | **0.3470** | **0.669** | — |
| G4 + topk 5（λ 仍被锁） | 0.4228 | 0.3289 | 0.7176 | 0.6375 |
| oracle（参照） | 0.9029 | 0.7669 | 0.9974 | 0.9974 |

**recall 翻倍（0.2206 → 0.4532），MRR +14.7pt。**

### ⚠️ 核心主张重验：总体差距缩小，但目标场景差距放大

修复后 G4 与 G2 都大幅提升，**总体差距从 +15.3pt 缩到 +5.7pt**——
说明原来的优势有相当部分来自"选源太差，多选能碰运气"。

但**分场景看，结论反而更强、也更精确**：

| scene | G2 单源 + fix | G4 多源 + fix | 差 |
|---|---|---|---|
| **multi_hop（跨会话聚合）** | 0.0714 | **0.2054** | **+13.4pt（2.9×）** |
| **temporal（跨时间）** | 0.4286 | **0.6000** | **+17.1pt** |
| single_hop（单会话） | **0.5435** | 0.5217 | −2.2pt |
| adversarial | 0.4000 | 0.4000 | 0 |
| open_domain | 0.4545 | 0.4545 | 0 |
| **总体** | 0.3935 | 0.4500 | +5.7pt |

→ **多源的价值高度集中在需要跨会话/跨时间聚合的场景**（multi_hop / temporal），
而在单会话场景（single_hop）单源反而略优。

**这个表述比笼统的"多对多 > 一对一"强得多，也更诚实**：
创新点应表述为「**跨智能体/跨会话的记忆共享调度**」——跨源才产生价值，这正好是主张本身。

### 遗留问题（必须处理）

1. **λ=0 最优意味着图边强度在 LoCoMo 上无价值**（λ=0.3 时 recall 掉到 0.3647）。
   辩护点：LoCoMo 的边是 **Jaccard 词面相似度**建的（§5.6 已证明它与相关性无关），
   边强度无预测力是**建边方式的问题**，不否定图机制本身。合成数据上 typed 边需重验。
2. **结果有波动**：同一配置两次跑出 recall 0.4532 / 0.4500、multi_hop 0.2232 / 0.2054。
   确定性链路不该有波动，需排查（疑似 faiss / 浮点 / warmup 顺序）。
3. **未做显著性检验**，且 G2/G4 都用 `force_lambda` 绕开了档位 → 需在正式实验里统一档位口径。
