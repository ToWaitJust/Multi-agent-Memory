## 0. 一页总结

| 维度 | 改造前（星形主副线） | 改造后（topic 图） |

## 1. 设计目标与边界

### 1.1 目标（用户本轮明确）
1. 由主副线升级为**图结构**：每个聊天会话 = 一个图节点，各节点拥有独立记忆。
2. **大记忆池方案**：每条记录做**节点标记**，低成本形成各节点专属记忆。
3. **边强度**驱动记忆**动态调度**。
4. **保留**思维注意力与可学习权重机制。
5. 重点优化**成本 / 效果 / 速度三角均衡**。

### 1.2 边界（不做的事）
| 不做 | 理由 |
|---|---|
| 多跳传播（depth>1 默认关） | 用户明确"不需要多跳"；多跳引入环与一致性问题 |
| 实体级知识图谱（实体对齐/关系抽取） | 节点粒度是 topic 会话，非实体；论文主动划界 |
| 图可视化 | 现画布是主副线视角，改图视图有量工作 → **P2 后置**，先 headless |
| 多进程/容器级隔离 | 沿用 D-3 逻辑隔离 |
| 推翻现有算法模块 | 改造面限定在"新增 + 插桩" |
| per-query 重算边强度 | 2026-09-07 已定案，静态（见 §4.2） |

## 2. 数据模型

### 2.1 记忆条目：扩展而非新建
`MemoryCandidate`（`attention.py`）**加两个字段**（带默认值，向后兼容）：
```python
owner_node: str = "main"   # ★ 生产者节点：这条记忆归哪个会话节点的"专属记忆"
producer_run: str = ""     # 产出它的调度轮次 id（溯源用，可选）
```
- **`owner_node` 是"大池 + 标记"的唯一新增标记**，也是节点专属记忆的过滤器。
- 向后兼容：`resident_pool.jsonl` 旧行无该字段 → 读入补 `"main"`（**只读补默认，不回写文件**）。
- **单值而非多值**（自评审决策）：一条记忆只归一个 `owner_node`；
  "公共信息被多个节点引用"用**图上的边**表达（`references` 边 + `min_quota=1`），
  不引入多值标记 —— 多值会让"倒排索引 O(1) 插入"变成多路写入，破坏"低成本"前提。

### 2.2 节点与边
```python
TopicNode: node_id / topic / summary / emb / owner_user / session_id /
           created_at / summary_at / version / root_id / status / n_memories
TopicEdge: edge_id / src / dst / type / strength / created_at / updated_at /
           evidence / stage(coarse|refined) / status(active|cycle_rejected) / similarity
```
**typed 边 → 默认强度**（唯一作用是初始化，不是装饰）：
`derives_from 0.9` / `depends_on 0.8` / `references 0.5` / `similar_to 0.3`。
相似度分档判型（无 LLM 时的确定性回退）：`≥0.85→derives_from / ≥0.72→depends_on /
≥0.58→references / 其余 similar_to`。

### 2.3 大记忆池 + 节点标记（低成本视图）
```
┌────────────────── EntityPool（唯一正文存储） ──────────────────┐
│  memory_id → { text, embedding(1024), meta, owner_node }       │
│  倒排索引 by_node: owner_node → [memory_id, ...]   ← 插入 O(1)  │
└────────────────────────────────────────────────────────────────┘
```
**为什么"低成本"**：零拷贝（正文/向量全项目一份）、零同步（更新只改一处）、
零额外 embedding 调用（借来的记忆复用其入库时的向量）、倒排索引**可从池重建**（不落盘、不新增侧表，保持 D-10）。

> **与旧"双池"的关系**：形态演进 —— `ResidentMemoryPool` 承担实体池角色；
> `SharedMemoryPool` **类与持久化格式保持不变**（否则 `/api/pools`、画布继承连线会读到空池），
> 语义收窄为"本轮调度产出的注入集快照"。

## 3. 图结构层（`srtp_memory/graph/graph_store.py`）

### 3.1 强制 DAG
- 加边前**可达性检查**：若 `dst` 已可达 `src`，则该边成环 → **默认拒绝建边**，
  降级为 `references` 且 `status=cycle_rejected`（**不入调度邻域**，仅溯源可见）。
- 提供 `topo_order()` / `assert_dag()`，单测强制覆盖。

### 3.2 环处理优先级
| 优先级 | 手段 | 说明 |
|---|---|---|
| **P0 主要** | 建边环检测 | 回边 → 拒统；改打 `references` |
| **P1 封顶** | 扩散深度 `depth=1`（默认） | Stage A 只展开一跳 |
| **P2 去重** | 路径去重 | 同 `memory_id` 多路径取最强一条 |
| **P3 兜底** | 版本化节点 | 仅显式延续 topic 时建；**默认折叠** |

### 3.3 邻域方向（实装时确定的关键点）
边语义统一为「**被依赖方 → 依赖方**」，因此**当前节点要取的源 = 它的入边起点**，
Stage A 使用 `GraphStore.predecessors()`（沿入边展开，强边优先），**不是** `neighbors()`（沿出边）。

### 3.4 两阶段建边（冷启动，`graph/builder.py`）
| 阶段 | 时机 | 依据 | 特点 |
|---|---|---|---|
| **粗识别** | 建节点时**立即** | `emb(topic 标题 + 首轮 query)` | 快，保证节点一诞生就有边可用 |
| **精识别** | `summary` 生成后 | `emb(summary)`（+ 可选 LLM 判型） | 准，**可覆盖**粗识别，须写 `evidence` |

边密度双阀：① 只与已有节点比（O(n)）；② 只保留 top-k（k=4）。
判据（Q6c）：精识别覆盖率应 <30%。

### 3.5 `summary` 的三条硬边界
1. **只用于建边与源打分，绝不用于记忆召回**（代码层强制：不进 `retriever` 输入）。
2. **失效重算**：触发 = 该节点新增记忆 ≥ `summary_refresh_n`（默认 20）；重算时能溯源 `memory_id`，
   并列出受影响需重判的边。
3. **细节丢失不影响书签**：书签（`path:line`）永远指向实体池原文。

## 4. 调度：Stage A + Stage B

### 4.1 管线全景
```
              ┌─────────── Stage A：选源（★ 新增）────────────┐
 n_cur+query ▶ ① predecessors(depth=1, 强边优先)
              ▶ ② 版本折叠 / 环降级边排除
              ▶ ③ 源打分 src_score = λ·strength + (1−λ)·rel
              ▶ ④ 源裁剪 top-k → 配额 / 偏置  → 源集合 S
              └──────────────────────────────────────────────┘
              ┌─────────── Stage B：选记忆（原样保留）────────┐
 大池按 S 过滤 ▶ ⑤ 范围内精确余弦召回（top_k=50）
              ▶ ⑥ 四维打分 f_d(m,q)，d∈{time,semantic,frequency,task}
              ▶ ⑦ 混合权重 w = α·w_prior(LLM) + β·w_MLP(condition)  α=.6 β=.4
              ▶ ⑧ final = Σ w_d·f_d / Σ w_d  (+ μ·src_score 若 soft_bias)
              ▶ ⑨ 选择 kept ≤10（自适应阈值）
              ▶ ⑩ 跨源合并 + memory_id 去重 → 注入集
              └──────────────────────────────────────────────┘
```

### 4.2 边强度是静态的（已定案，代码级约束）
| | `strength`（边强度） | `relevance`（查询相关度） |
|---|---|---|
| 谁的属性 | **节点间关系**的属性 | **query × 节点**的属性 |
| 依赖 query | **否** | 是 |
| 何时算 | **建边时一次算好** | 调度时算 |
| 何时变 | 建边 / 用户反馈 / summary 重算 | 每次 query |

```
src_score_i = λ · strength(edge(n_cur → s_i)) + (1−λ) · cos(emb(topic_i), emb(q))
λ = 0.7   固定架构超参，不进消融变量链（改做附录敏感性分析 λ∈{0.5,0.7,0.9,1.0}）
```
- **零成本论证**：`emb(q)` 复用 Stage B 语义头本来要算的那一次；`emb(topic_i)` 建节点时已缓存；
  增量仅 m 次内积（m=2~5），亚毫秒。
- **退化保护**：各源 `rel` 方差 < 阈值（默认 0.02，**待标定**）→ 令 λ=1 退回纯静态。
- **代码约束**：任何地方**不得**把 query 信号写回 `edge.strength`
  （由 `tests/test_graph.py::test_edge_strength_is_static` 守护）。

### 4.3 配额：两种模式并存（POC 两轮结论冲突的处置）
POC 第一轮实测 **填充式配额 ≡ 封顶式配额**（Σquota=K 且每源池 ≥quota 时数学等价），
因此硬配额只有一种有效语义；但第二轮真实数据上软偏置未复现优势 →
**两种都实现**，消融主链用 `strength`，`soft_bias` 作内部调参项：

| `quota.mode` | 语义 | 用途 |
|---|---|---|
| `none` | 只用邻域限定，不做源偏向 | G0/G1 下界 |
| `uniform` | 各源等权硬配额 | G3 |
| `strength` | 硬配额 `max(1, round(K·softmax(src_score/τ)))` 归一回 Σ=K | G4（主链） |
| `soft_bias` | `final += μ·src_score` 加性偏置，不设硬配额 | 内部调参 / 附录 |

⚠️ **实装后的补充结论（首轮实验）**：硬配额只在「**源池条目数 > 单源配额**」时才有区分度；
本数据集源池仅 4 条 < 配额 → G3≡G4（K=4 探针亦复现）。详见 §12。

### 4.4 节点专属记忆如何"真的独立"
- 节点**只**从 `by_node[n_cur]`（自己产出的）+ 邻域源节点池召回，**不**全池召回 → 解决"远丢失"。
- 子节点产物写回大池时打 `owner_node = 该子节点` → 主线过滤时天然看不到，
  主线纯净性由「标记 + 过滤」保证，而非靠"物理另一个池"。

## 5. ★ 成本 / 效果 / 速度三角均衡（本轮新增，重点）

### 5.1 三个量的可测定义
| 量 | 度量 | 来源 |
|---|---|---|
| **成本 C** | `llm_calls`（LLM 调用次数）/ `embed_calls_miss`（**只计未命中缓存**的 embedding 调用）/ `injected_tokens`（注入长度粗估） | `schedule.jsonl` 新增字段 |
| **效果 E** | `recall_acc`（+ `source_hit_rate` / `multi_source_ratio`） | `data/runs/` |
| **速度 T** | `latency_ms.total` 的 P50 / P90 | `schedule.jsonl` |

### 5.2 三层机制
**机制一 · 成本侧**：先验 LRU 缓存（key = 归一化 query + condition，命中 = 0 次 LLM 调用）；
`llm_calls_per_schedule` 预算（默认 1，可设 0）；建边批量判型 + 宽容解析 + 重试上限。

**机制二 · 速度侧**：三档 `perf_tier`

| 档 | LLM 先验 | 候选集 | Stage A | 定位 |
|---|---|---|---|---|
| `full` | 实时调用 | 50 | λ=0.7 | 效果优先 |
| `balanced` | 缓存优先 | 30 | λ=0.7 | **默认** |
| `fast` | 跳过 | 20 | λ=1.0（纯静态） | 速度优先 |

滞回升降档：最近 20 次 `P90 > budget` → 降一档；`P50 < 0.45·budget` 连续 3 窗 → 升一档。
⚠️ **`budget.adaptive` 默认 `false`（锁定档位）** —— 自适应会让同一实验在不同负载下走不同档位，
破坏 NFR-6 可复现性；演示/真实交互才开。

**机制三 · 效果侧（门控，把钱花在刀刃上）**：五重门控按"先便宜后昂贵"顺序 ——
`tier_off`（档位为 fast）→ `cache_hit`（0 成本）→ `budget`（额度用尽）→
`few_cand`（候选 ≤5，权重影响微乎其微）→ `low_src_var`（源不可区分）。
Stage A 的 `rel` 项与四维打分**均为纯 CPU**，不计成本 → 默认全开。

### 5.3 综合目标函数（论文里画 Pareto）
```
J = E_norm  −  γ_C · C_norm  −  γ_T · max(0, P90_T / budget − 1)
```
⚠️ **诚实边界**：阈值与门槛常量是**工程启发式**。论文只应报告"三档的 (E, C, T) 取点与 Pareto 曲线"，
**不主张** `J` 是可优化目标；`γ_C/γ_T` 无客观依据。

## 6. 消融设计

### 6.1 主链 G0–G4（5 组，替换原 5 组）
| 组 | 图 | Stage A 选源 | Stage B | 配额 | 证明什么 |
|---|---|---|---|---|---|
| **G0** | ✓ | 邻域全量 | ✗ | none | 下界：有图也不调度 |
| **G1** | ✓ | 邻域全量等权 | ✗（写入序） | uniform | 下界：**算法贡献的对照（Q1）** |
| **G2** | ✓ | **只取强度最高 1 个源** | ✓ | n/a | **主副线等价物 ★** |
| **G3** | ✓ | 多源（top3）等权 | ✓ | uniform | 剥离"边强度配额" |
| **G4** | ✓ | 多源（top3）按边强度 | ✓ | strength | 完整方案 |

**三条主打对比**：`G0→G1` 证明需要调度；`G2→G3` 证明**多对多优于一对一**（核心创新点）；
`G3→G4` 证明边强度配额有效；`G1→G4` 证明**增益来自算法而非图结构**（必须报告）。

**控制变量**：五组 `retriever_impl` 统一 `retriever.vector`；`graph.enabled=true` 五组同开；
`quota_lambda=0.7` 与 `depth=1` 五组共用；**图结构由数据集固定注入**（`auto_link=false`）。

### 6.2 附录 A：均衡档 —— 单变量扫描 + 组合实测点
| 组 | 唯一变量 | 其余保持 full 档 |
|---|---|---|
| **B0** `full` | —（基准） | LLM 实时 / cand=50 / λ=0.7 |
| **B1** `no_llm` | 去掉 LLM 先验 | cand=50 / λ=0.7 |
| **B2** `small_cand` | 候选 50 → 20 | LLM 实时 / λ=0.7 |
| **B3** `pure_static` | λ 0.7 → 1.0 | LLM 实时 / cand=50 |
| **B4** `balanced` | 组合实测点 | 即默认线上档 |

### 6.3 新增指标（4 个）+ 必报项
`source_hit_rate` / `multi_source_ratio` / `cross_source_relevance` / `dedup_rate`，
以及 **`ceiling = min(1, K/|relevant|)`**（POC 教训：不报天花板会把物理上限误读为方法优势）。
> 实装发现：`owner_node` 单值标记 → 各源池互斥 → **`dedup_rate` 结构性恒为 0**，不得作为证据。

### 6.4 判据（go / no-go）
| 判据 | 阈值 | 不通过时 |
|---|---|---|
| 结构主张 | `G4.recall > G2.recall` 且 `G4.src_hit > G2.src_hit` | 归档图方案 |
| 归因（Q1） | `(G4 − G1)/ceiling ≥ 5%` | 承认图结构贡献为主 |
| 选源层（Q2） | `G4.src_hit − G3.src_hit ≥ 8%` 且 G4 召回不降 | 简化 Stage A |
| 均衡 | `B4` 相对 `B0` 效果损失 ≤2pt 且 P90 降 ≥25% | 调 μ / 阈值 |
| 速度 | G4 P90 < 1000 ms | 强制降档并报告 |
| 多源生效 | 多源样本 `multi_source_ratio > 0.3` | 先查配额/去重 bug |

## 12. 首轮实验结果与判据修订（v1.2）

完整数据与八条发现见 [待审交付包_20260922](待审交付包_20260922.md) §实验部分。摘要：

```
G0 0.9808 | G1 0.9615 | G2 0.8077 | G3 0.9423 | G4 0.9423 | G4-oracle 0.9423   (recall)
G2 src_hit 0.8654  →  G3/G4 src_hit 1.000 ;  多源样本 multi_source_ratio 0.381
```

### 12.1 一句话结论
**结构价值证明成立（G4 > G2：recall / src_hit 各 +13.5pt），算法价值证明失败（G4 − G1 = −1.92%）。**

### 12.2 判据修订（区分"未通过"与"不可辨识"）
| 原判据 | 实测 | 诊断 | 处置 |
|---|---|---|---|
| 归因 `G4 − G1 ≥ 5%` | −1.92% | **失败是真的**（打分器排序质量不足） | **不改判据**，升级为**前置阻塞项 S0** |
| 选源层 `G4 − G3 ≥ 8%` | 0.0 | **在数据结构上不可辨识**（源池 4 条 < 配额；K=4 探针复现） | 补前置条件（每节点 ≥20 条），否则标记 `N/A 待复测` |
| 需要调度 `G1 > G0` | −1.93% | 两组都是"无算法"下界，差异无方向性 | 降级为**参考读数** |
| 均衡 `B4` vs `B0` | 三档零差异 | 三旋钮作用区间**都没被触及**（无 LLM key / 池 <20 / 源 ≤3） | 补前置条件后复测 |
| 压缩比 ≤0.3 | 0.75 | 邻域本身仅 ~5 条候选 | 大池数据集上复测 |

> **修订原则**：判据"未通过"是**结论**（要如实报告）；判据"不可辨识"是**实验设计缺陷**（要补前置条件）。
> 后者靠独立探针（K=4）与机制审查支撑，不是找台阶。
