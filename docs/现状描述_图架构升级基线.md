## 2. 架构现状

### 2.1 主副线（星形，改造前基线）
```
用户提问 → MemorySchedulingMiddleware.schedule_once()
            └→ MemoryCoordinator（持 常驻完整池 + 共享池）
                 ① 召回 retriever.recall(query, pool, top_k=50)
                 ② 权重 weights.calculate(query_emb, condition)  ← α·LLM先验 + β·MLP
                 ③ 打分 scorer.score(...)                         ← 四维注意力
                 ④ 选择 selector.select(...) → kept ≤10
                 ⑤ 写池 shared_pool.add() + resident_pool.mark_access()
                 ⑥ 埋点 logger.log_schedule() → data/metrics/schedule.jsonl
            └→ dispatch() → 副线 SubAgent（只看到 ≤10 条，看不到常驻池）
```
- **隔离本质（D-3）**：逻辑隔离，非进程隔离（独立 Agent 实例 + workspace 路径 + session_id）。
- **池结构**：`ResidentMemoryPool`（JSONL + faiss 索引，全量正文）+ `SharedMemoryPool`（有序、≤10）。
- **检索基座**：5 种可插拔（`full`/`bm25`/`vector`/`rrf`/`reme`），插件注册表 `plugins/`。
- **配置真源**：`config/srtp.yaml`（`*_impl` 字段装配）；消融在 `config/ablation/*.yaml`。

### 2.2 已锁定的设计决策（不要重新讨论）
| 编号 | 决策 |
|---|---|
| D-3 | 单进程本地运行；多智能体 = 逻辑隔离 |
| D-5 | embedding 用 DashScope `text-embedding-v4` **1024 维**（论文称"替代 BERT 的轻量向量化"） |
| D-9 | 记忆检索**只有一个入口**（调度管线），ReMe 只写回 |
| D-10 | 无 `memory_meta` 侧表，元数据直接进 `resident_pool.jsonl` |
| D-11 | 真实 API 失败自动降级（占位向量 / DEFAULT_WEIGHTS），pipeline 不中断 |
| D-12 | ReMe 检索算法**中性化**（不叠加 RRF/wikilink），保归因干净 |
| D-13 | LLM 先验用**轻量小模型单次采样**（预算 ≤800ms，保 NFR-1 <1s） |
| — | α=0.6 / β=0.4 **固定不可学**；语义头内部 W_COS/W_VEC/W_BM25=0.5/0.3/0.2 与 α/β 无关 |
| — | 候选集固定 **50**、共享池固定 **≤10**；共享池**不做二次检索** |
| — | 条件化只作用于 `semantic` / `task`；`time` / `frequency` 全局 |
| — | 反馈 reward ∈ {+1, −1}，bandit 式一步更新，只更新 condition 切片（REQ-405 正则） |

## 4. 实验现状（★ 最需正视的一节）

### 4.1 原 5 组消融：**跑过，但结果不可用**
`data/runs/ablation_summary.json`（2026-08-25，mode=offline，n_episodes=20）三处明显退化：

| 症状 | 证据 | 推断根因 |
|---|---|---|
| `baseline_naive` ≡ `baseline_reme` | 两组同为 0.5 / 0.1 / rank 5.4 | 离线下 `retriever.reme` 未生效，退化成 `full` |
| `+attention` ≡ `+weight` | 两组同为 1.0 / 0.2 / rank 1.05 | `weight.full` 与 `weight.uniform` 无差异（MLP 未训练） |
| `full_ours` 的 `avg_kept=0.8` | precision 0.8 但 rank 5.4，自相矛盾 | 保留不足 1 条 → 小分母假象 |

> 结论：**消融"跑过" ≠ "可用"**。此外 `full_ours` 单独换检索器已造成归因污染
> （见 §2.2 D-12 同源问题），图版消融已统一为 `retriever.vector`。

### 4.2 图架构首轮实验（本日完成，数值可复现）
数据：`data/graph_dataset.jsonl`（14 节点 / 21 边 / 56 记忆 / 26 episodes / 7 条多源查询）；
真实 DashScope embedding。**完整结果与八条发现见 [待审交付包_20260922](待审交付包_20260922.md)**。

```
G0 0.9808 | G1 0.9615 | G2 0.8077 | G3 0.9423 | G4 0.9423 | G4-oracle 0.9423   (recall)
G2 src_hit 0.8654  →  G3/G4 src_hit 1.000
```
- ✅ **核心主张成立**：G4 > G2，recall 与源覆盖**各 +13.5pt**。
- ❌ **算法层未成立**：`G4 − G1 = −1.92%`（G0/G1 反超）→ 打分器排序质量不足。
- ❌ **G4 ≡ G3**：边强度配额不 binding（源池 4 条 < 配额；K=4 探针复现）。
- ✅ 自动选源已达 oracle 上界；多源样本 `multi_source_ratio = 0.381`。
