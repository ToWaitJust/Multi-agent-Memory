## 已确认（全部维度 2026-08-18 锁定）

### D1 交付物形态
- **核心（headless）**：调度中间件 `MemorySchedulingMiddleware` + 权重模型（条件化 MLP β + LLM 先验 α）。可单测、可消融（REQ-610），不依赖任何 UI。
- **外壳（演示）**：Electron 多窗口演示壳（主线窗 / 副线窗，REQ-201，P2，可后置到 V1.1+）。
- **原则**：核心与 UI 解耦；UI 只是核心之上的一层壳，可被 CLI / 测试 / 消融脚本直接驱动核心。

### D2 目标用户
- **研究者自用**：自己跑实验、写论文、答辩演示；**不是**终端消费者产品。外壳只为展示方法，不做产品化打磨。

### D3 运行形态
- **本地单机（单进程）**：V1 单进程内多 Agent + 共享协调器实例（REQ-104）。
- 多智能体协作 ≠ 多进程；主副线隔离靠逻辑隔离（独立 context + 双池读写分离 + session_id 隔离，NFR-7），不靠 OS 进程边界。多进程 / 服务化为后续阶段可选项（REQ-104 列 P2）。

### D4 交互界面
- 核心：headless API（CLI / 单测 / 消融脚本可直接驱动）。
- 外壳：Electron 多窗口演示（主线窗 / 副线窗，REQ-201，P2 后置到 V1.1+）。

### D5 完成定义（验收标准）
- **跑通 + 可消融验证**：全链路跑通（主线→协调层→共享池→副线）+ 四维打分 / 混合 / 动作选择 + 条件化权重（仅语义/任务个性化）+ 反馈闭环（RL 点赞/点踩）+ 消融指标落盘（run_manifest + JSONL）。

## 由此回推的工程结论（待落到工程文档 V1.1）
- 核心代码库（headless）是主线工作量；Electron 壳可后置、可最简。
- 模块边界：调度中间件 / 权重模型(weights) / 选择器(selector) / 双池存储适配 / 实验指标落盘，均可在单进程内以 Library + CLI 形态先交付。
- 单进程 + 共享协调器 → 主副线用同一进程内对象通信，无需 IPC；隔离靠逻辑层。
- 消融(REQ-610)与指标落盘(REQ-706)是一等公民，核心须从第一天就带埋点。
