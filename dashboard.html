副线架构（书签定位式 · 隔离 workspace）

发送问题后，这里显示副线书签：调度层把共享池精选记忆注入各副线隔离 workspace。
双池架构说明（点开）

常驻完整池（Resident Pool）：每个用户的全量记忆向量库（faiss ANN 索引），是主线智能体（MainAgent）的全量只读上下文。所有新记忆先 upsert 进此池，召回在此池上进行。

共享池（Shared Pool）：调度层用四维注意力 + 混合权重从常驻池精选 ≤10 条高相关记忆写入的向量集，是副线智能体（SubAgent×N）隔离 workspace 的输入。副线只看到这 ≤10 条，看不到主池全量，从而实现主副线逻辑隔离（D3）。

调度运作：查询 → 常驻池向量召回候选 → 四维打分（时间衰减/语义相似/访问频率/任务匹配）→ 混合权重（α·LLM先验 + β·可学习权重）→ 按 final 排序 → 阈值选择 ≤10 写入共享池 → 主线 Agent 基于共享池作答；同时共享池经 coordinator.dispatch() 注入各副线沙箱（书签定位）。

两个池的载体都是向量数据库：上方左图为常驻池语义分布（PCA 2D 投影），右图为共享池精选集。视觉约定（避免误读）：蓝高亮●=本轮召回候选，绿实心◆+动画连线=本轮真正保留进共享池（连线表示「常驻池→共享池」注入流向），空心蓝边○=历史留存（上一轮就留在池里、本轮并未调度，不画连线）。下方两个副线框是与主线并列的独立 Agent 实例：共享池经 coordinator.dispatch() 注入其隔离 workspace（虚线箭头），副线只读共享池、不触常驻池（D3 逻辑隔离）。
