## 第一轮的 4 个结论（比 go/no-go 本身更值钱）

1. **机制全部跑通**：图 → 选源 → 四维打分（复用 `attention.full`）→ 合并去重 → 指标 → 自动判据。
   工程可行性（02 的 Q5）从"纸面确认"升级为"代码验证"。

2. **填充式配额 ≡ 封顶式配额（G4 ≡ G4C，实测完全一致）**。
   数学原因：当 Σquota = K 且每个源池 ≥ quota 时，"全局排序+每源封顶"必然退化为"每源填满配额"。
   → **硬配额只有一种有效语义，想区分就必须用软偏置（G4S）**。03 的消融设计应据此修订。

3. **ground truth 松紧会制造天花板假象**。第一版"任一关键词命中即相关"让相关集（≈15 条）
   超过注入上限 K=10，所有组的 recall 被 `10/|relevant|` 压死，G2 的 0.667 就是天花板而非优势。
   → 正式实验必须报告 **|relevant| 与 recall 天花板**，否则指标不可解释。

4. **合成数据上 G2 赢是构造的产物**：我造数据时让最强边恰好指向最相关节点（强度与相关性完美相关），
   G2 的 0.750 是"作弊"来的；其 src_hit 只有 0.667（漏掉 1/3 的相关源）才是真实代价。
   **判据（G4S vs G2）在合成分布上不可辨识 → 本轮不出 go/no-go，直接进 Q4 真实数据。**

## 值得带进真实数据的一个信号

G4S（软偏置 μ=0.2）在 recall（0.708）与 src_hit（0.917）之间取得了比硬配额（G4：0.625/1.000）
更好的平衡——硬配额为了"源覆盖"牺牲了 12 个点的 recall。真实数据上值得把 μ 扫一遍（0.1/0.2/0.3）。

### 第二轮的 4 个读数

1. **核心主张在真实数据上成立**：多源调度（G3/G4）比单源（G2）recall +6.5pt、源覆盖 +42pt。
   G2 的 0.583 源覆盖是实打实的代价——单源错过了近一半该参考的模块。
2. **G4 ≡ G3 的原因不是等价定理，是数据**：7 条边全是 depends_on(0.8)，强度零方差。
   λ·strength 项是否有增量，需要一个混合 derives_from/references 边的数据集（生成器已支持 typed 边，换场景即可）。
3. **G1（写入序）0.765 反而最高** → 四维打分器在真实数据上疑似被 频率噪声/时间衰减 拖累，
   在源内排序里不如写入序。这正是主线消融三处退化要诊断的同一批问题（同一个打分器）——两条线在此汇合。
4. **软偏置 G4S 本轮不敌硬配额**：μ∈{0.05..0.3} 扫过，recall 最高 0.676(μ=0.05) 仍 < 0.726。
   第一轮"软偏置更平衡"的信号在真实数据上未复现——合成结论到真实数据会翻车，又一次验证。

### 对判据的修订（已写回代码）

写死判据原把 G4S 当 G4 的代理，实际应分开：**结构主张用 G4 vs G2 检验**；
强度主张仅在边强度方差 > 0 时检验（否则 N/A）；G4S 是 μ 调参的内部选项，不进主判据。
