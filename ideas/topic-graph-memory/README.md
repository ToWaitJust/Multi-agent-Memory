## 为什么单独开这个目录

1. **隔离风险**：这个 idea 会推翻"主副线"这一架构基底，属于高不确定性改动。放在主文档里会污染已定稿的需求清单、验收标准与消融设计。
2. **便于放弃**：如果验证不通过，直接删目录，主文档零改动。
3. **便于讨论**：初稿需要被反复批判和修改，与"已定稿"的文档混在一起会分不清哪些是决策、哪些是猜想。

## 最新澄清（2026-09-07）

> **边强度是静态的，不 per-query 重算。**
> `strength`（节点间关系，建边时一次性算好）与 `relevance`（query × 节点，调度时算）是两个不同的量；
> 调度用 `λ·strength + (1−λ)·relevance`（λ=0.7 固定超参）。
> 关系识别在**节点形成时**完成（粗识别 → summary 后精识别），详见 `01_idea_draft.md` §4.5 / §7.1 与 `02_open_questions.md` Q8。

## 一句话版本

把记忆调度的作用域从"主线 ↔ 单个副线"的一对一星形拓扑，换成**以 topic 会话为节点、以关系为边的有向无环图**；
调度从"一对一筛选"进化为"**先选源、再选记忆**"的多对多筛选；
**创新点仍然在调度算法，图只提供结构先验**——二者必须解耦，否则增益会被归给图结构。

## 与主架构的关系（重要）

- **不写"主副线 → 图"的演进叙事**。论文中直接从图讲起，避免审稿人追问"提升来自图结构还是调度算法"。
- 主副线降级为消融组 **G2（图 + 单源调度）** 的等价物——它证明"多对多优于一対一"，是消融链上关键的一环，而不是被演进掉的历史包袱。
